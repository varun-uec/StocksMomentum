Severity follows the audit definitions: P0 critical data/security/financial failure; P1 broken critical workflow, incorrect persisted state or major regression; P2 non-critical defect/usability problem; P3 optional polish. “Fixed” means the regression is covered and the post-fix check passed. Evidence links include browser screenshots/traces where visual behavior applies; API/domain corrections use the corresponding automated regression test.

## P0

**None observed.** This is not a claim that Wickstreet has been security-audited for public-network deployment; it is a local, anonymous, loopback application.

## Release gates (not ranked as software defects)

1. The project’s [NSE data-use review](docs/history/audits/2026-10-19-m16-nse-data-use.md) concludes that the app's scheduled automated collection and simulation use conflict with terms cited in that review. Obtain written permission/licensed feed, obtain a legal resolution, switch to a permitted provider or remove built-in fetching before public release. No NSE automated download was triggered in this audit. This records the project review; it is not legal advice.
2. [ADR-015 licence](docs/architecture/adr/ADR-015-licence.md) is proposed, not accepted. Formal Wickstreet trademark/domain clearance is also incomplete.
3. There is no authentication. The deployment is private/loopback by default; do not expose it as a public multi-user service.
4. Existing research data shows negative qualified-set ranking IC (−0.0384 mean 120-day IC, t −2.43, 63 monthly runs); no research proposal passed holdout. Product copy must not imply validated investment returns.

## Test and audit limitations

No unresolved P0/P1 defect was observed in the high-priority workflows that were exercised. The user's full exit criteria are **not fully satisfied** because some exhaustive permutations were not run: every drawing tool was created, but all edit lifecycle actions were not repeated for every tool; the entire Studio parameter/holdout/failure matrix was not browser-driven; alert corporate-action re-evaluation was not exhausted; durable DB recovery and several API failure modes were not injected; and there was no full accessibility or memory-soak test. Details are in the [coverage matrix](E2E_COVERAGE_MATRIX.md).
