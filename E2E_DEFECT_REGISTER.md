Severity follows the audit definitions: P0 critical data/security/financial failure; P1 broken critical workflow, incorrect persisted state or major regression; P2 non-critical defect/usability problem; P3 optional polish. “Fixed” means the regression is covered and the post-fix check passed. Evidence links include browser screenshots/traces where visual behavior applies; API/domain corrections use the corresponding automated regression test.

## P0

**None observed.** This is not a claim that Wickstreet has been security-audited for public-network deployment; it is a local, anonymous, loopback application.

## Release gates (not ranked as software defects)

1. Direct exchange downloads now default off and are not required for distribution. Do not enable optional NSE/BSE adapters unless the operator has confirmed permission for the source and intended use. Authorized-data CSV imports are documented. The [NSE data-use review](docs/history/audits/2026-10-19-m16-nse-data-use.md) records why the prior default was not release-safe; it is not legal advice.
2. [ADR-015 licence](docs/architecture/adr/ADR-015-licence.md) is proposed, not accepted. Formal Wickstreet trademark/name clearance remains incomplete; these are publication decisions.
3. The application has no authentication and is designed for one local user bound to loopback. A network-exposed instance is not secure; require an authenticating proxy before any network exposure. This does not make the source distribution a multi-user service.
4. Existing research data shows negative qualified-set ranking IC (−0.0384 mean 120-day IC, t −2.43, 63 monthly runs); no research proposal passed holdout. Product copy must not imply validated investment returns.

## Test and audit limitations

No unresolved P0/P1 defect was observed in the high-priority workflows that were exercised. The focused pass exercised all 12 drawing tools through draw/select/move/recolor/undo/redo/delete/restore; Strategy Studio insufficient-data rejection and a matured one-shot hold-out; a split/bonus-adjusted alert threshold; and browser state recovery after restarting a named-volume PostgreSQL container. Five importer/policy/run API integration tests passed on a disposable `_test` database. It did not exhaust every Studio parameter constraint, all alert value/interval permutations across corporate actions, DB outage mid-write, corrupted-document permutations, or a full accessibility and memory-soak test. See the updated [coverage matrix](E2E_COVERAGE_MATRIX.md) and hardening addendum in the [audit report](E2E_AUDIT_REPORT.md).
