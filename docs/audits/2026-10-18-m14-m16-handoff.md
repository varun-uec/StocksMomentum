## 4. Decisions taken in M14 so far

- **Schemas are enforced where a strategy is written, not where it is read.** A stored strategy must stay readable as it was run (ADR-005).
- **Bounds are wide** and keep values meaningful (percentiles 1–99; windows fit the 252-session history). They do not narrow today's settings. All seven strategy files and every stored strategy validate.
- **`risk_extension` defect fixed.** It read `ma` but always measured against SMA 50. Production uses 50, so no production result changes. Its `ma` is now limited to the computed windows: 50, 150 and 200.
- **`securities` is versioned** although ADR-014 did not list it: its listing and delisting dates decide the point-in-time universe. **`universe_membership` is not**: it is a per-run output.
- **One global revision sequence** stands in for per-table high-water marks. It is simpler, and one number rebuilds every table.
- **`adj_factor` and `adj_close` are not versioned.** They are derived, every new corporate action rewrites them in bulk, and the point-in-time port recomputes factors from the actions themselves.
- **Provenance is set by the trigger from timing.** A row stored within 4 days of its session or ex-date is `recorded`, otherwise `published`. `historical_universe` defaults to `reconstructed`. Today every stored row is `published`, at revision 0.
- **The test schema is rebuilt each pytest session** (`drop_all`, then `create_all`, behind the `_test` guard), because `create_all` never alters an existing table.
